# ADR-001: 音声APIの選定

| 項目 | 内容 |
|---|---|
| **ID** | ADR-001 |
| **状態** | 確定 |
| **決定日** | 2026-04-25 |
| **関連制約** | Constitution §4 レイテンシ20ms以下、音声API: AAudio/Oboe |

---

## 背景

DJアプリの核心は音声処理である。クロスフェーダー・EQ・スクラッチ・ループは全て音声バッファを
リアルタイムで操作する必要があり、レイテンシと柔軟性が最重要要件となる。
Androidには複数の音声APIが存在し、特性が大きく異なる。

---

## 選択肢の比較

### Option A: **Oboe（推奨）**

> GoogleのオープンソースC++ライブラリ。AAudio / OpenSL ES を自動的に使い分けるラッパー。

| 項目 | 評価 |
|---|---|
| レイテンシ | ◎ 最小（Pixel 8 Pro実測 約5〜10ms） |
| 柔軟性 | ◎ バッファ単位で音声データを直接操作できる |
| 対応APIレベル | ○ minSdk 16以上（AAudioはAPI 26以上で自動切替） |
| 実装コスト | △ C++（NDK）の知識が必要 |
| メンテナンス | ◎ Google公式メンテナンス中 |
| 採用実績 | ◎ GarageBand Androidライク、多数のプロ音楽アプリ |

### Option B: AudioTrack（Java/Kotlin）

> Android標準のJava音声出力API。PCMデータをJVMから直接書き込む。

| 項目 | 評価 |
|---|---|
| レイテンシ | △ 20〜50ms（JVM GCの影響を受ける） |
| 柔軟性 | ○ バッファ単位で操作可能 |
| 対応APIレベル | ◎ API 3以上 |
| 実装コスト | ◎ Kotlinのみで実装可能 |
| メンテナンス | ○ 標準API |
| 採用実績 | ○ 一般的なアプリ。音楽制作系では不十分な場合あり |

### Option C: ExoPlayer / Media3

> Googleの高機能メディア再生ライブラリ。ストリーミングや動画に強い。

| 項目 | 評価 |
|---|---|
| レイテンシ | ✗ 再生特化。リアルタイム音声操作は非対応 |
| 柔軟性 | ✗ バッファ直接操作不可。EQ・スクラッチ実装困難 |
| 対応APIレベル | ◎ API 21以上 |
| 実装コスト | ◎ Kotlinのみ |
| メンテナンス | ◎ Google公式 |
| 採用実績 | ◎ YouTube等。ただしDJ用途には不向き |

---

## 推奨: **Option A — Oboe**

### 理由
- レイテンシ20ms以下（Constitution §4）を達成できる唯一の選択肢
- Pixel 8 Pro + AAudioの組み合わせで実測5〜10msが期待できる
- バッファ単位の音声操作により、クロスフェーダー・EQ・スクラッチ・ループを全て実装可能
- C++実装コストはあるが、音声エンジンの範囲に限定すれば管理可能

### トレードオフ
- Kotlin + C++（JNI）の混在が必要になる
- 設計工程でC++音声エンジンとKotlin UIの境界を明確に定義する必要がある

---

## 決定

**Option A — Oboe を採用する。**
レイテンシ20ms以下（Constitution §4）を確実に達成するため。
C++ NDKの実装コストはAudio Engine Layerに限定し、Kotlin UIとはJNI境界で分離する。
