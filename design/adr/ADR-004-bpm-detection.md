# ADR-004: BPM検出ライブラリの選定

| 項目 | 内容 |
|---|---|
| **ID** | ADR-004 |
| **状態** | 確定 |
| **決定日** | 2026-04-25 |
| **関連制約** | Constitution §4 オフライン完結、UC-004 BPM精度±0.5以内 |

---

## 背景

BPM検出はトラックの波形解析が必要でCPU負荷が高い。
精度（±0.5 BPM）・オフライン動作・Androidとの統合性が選定基準となる。

---

## 選択肢の比較

### Option A: **aubio（C ライブラリ / NDK）（推奨）**

> オープンソースの音楽解析Cライブラリ。BPM・ビート検出に特化。

| 項目 | 評価 |
|---|---|
| 検出精度 | ◎ ±0.5 BPM以内を達成（学術論文でも使用実績多数） |
| ライセンス | ◎ GPL-3.0 → 商用配布時は注意が必要（後述） |
| オフライン | ◎ 完全オフライン動作 |
| Android統合 | △ NDK（C）ビルドが必要。CMakeで統合 |
| メンテナンス | ○ アクティブなOSS |

**ライセンス注意:** GPL-3.0のため商用アプリ（Google Play有料配布）の場合は
ソースコード公開義務が発生する。無料アプリ・OSS公開前提なら問題なし。
商用有料配布を検討する場合は、コマーシャルライセンスを別途検討する。

### Option B: **TarsosDSP（Java ライブラリ）**

> Java実装の音楽解析ライブラリ。Android対応フォークあり。

| 項目 | 評価 |
|---|---|
| 検出精度 | ○ ±1〜2 BPM程度（aubioより低め） |
| ライセンス | ◎ Apache 2.0。商用利用に制限なし |
| オフライン | ◎ 完全オフライン動作 |
| Android統合 | ◎ JVM上で動作。NDK不要 |
| メンテナンス | △ メンテナンスが不定期 |

### Option C: **独自実装（FFT + ピーク検出）**

> Kotlinで自前のBPM検出アルゴリズムを実装する。

| 項目 | 評価 |
|---|---|
| 検出精度 | △ 実装品質に依存。精度保証が難しい |
| ライセンス | ◎ 問題なし |
| オフライン | ◎ 完全オフライン動作 |
| Android統合 | ◎ 依存なし |
| 実装コスト | ✗ 高い。DSP知識が必要 |

---

## 推奨: **Option B — TarsosDSP（初期）→ Option A — aubio（精度向上時）**

### 理由（段階的アプローチ）
1. **Phase 1（初期実装）**: TarsosDSPで早期に動くものを作る
   - Apache 2.0ライセンスで商用展開に柔軟
   - NDKビルド不要でセットアップが速い
   - 精度±1〜2 BPM → DJアプリの初期版として許容範囲

2. **Phase 2（精度改善）**: aubioへの切り替えを検討
   - ±0.5 BPM仕様（AC-004-01）を厳密に満たすには aubio が有利
   - Google Play無料配布前提であればGPL-3.0も許容可能
   - Repository抽象化により差し替えが容易（ADR-003のClean Architecture前提）

---

## 決定

**段階的アプローチを採用する。**
- Phase 1: TarsosDSP（Apache 2.0、NDK不要で早期実装）
- Phase 2: 精度±0.5 BPM未達の場合にaubioへ切り替えを検討する
  （その際はライセンス条件を再確認すること）
Repository抽象化（ADR-003）により差し替えはUseCase以下に影響しない。
